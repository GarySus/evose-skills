# 操作知识

来自截至2026-10-23的特定部署观察。以下路径、控件与限制需在当前部署复核。

## 定位与浏览器状态

| 目标 | 候选路径 |
|---|---|
| Skill 列表/配置 | `/workspace/<workspace_id>/scalability/skill[/<skill_id>/configure]` |
| Agent 配置 | `/workspace/<workspace_id>/build-service/agent/<agent_id>/configure` |
| Workflow 列表 | `/workspace/<workspace_id>/build-service/workflow` |
| Workflow 配置 | `/workspace/<workspace_id>/workflow/<workflow_id>/configure` |
| 计划 | `/schedule` |
| IM 管理 | `/system/integration/im-apps` |
| 正式会话 | `/?app_id=<agent_id>&type=single_agent&session_id=<session_id>` |

真实ID从当前UI或用户链接取得。优先用[导航助手](fast-navigation.md)。恢复TaskSpace先盘点tabs，使用实际返回的控制引用；finish后旧标签可能已失效。工作台入口可能在原页跳转，先查当前页与tabs，不因popup超时重复点。首页无会话参数时同时核对Agent名称及新会话状态。

## 观测追踪与故障定位

1. 目标工作空间 → 观测 → 追踪 → 会话。优先按正式链接中的session_id搜索；无ID时按应用、用户和时间筛选，核对空间、标题与开始时间。
2. 零结果先检查时间和来源：管理台、开放API、桌面端、IM等。计划可从最近执行取得真实会话。配置右侧调试区不是完整历史工程日志。
3. 先顺序读用户输入与各轮 `agent.run` 最终回复，找第一次偏离意图。拒绝、追问和漏展示不一定有ERROR。
4. 展开轮次及树形/链路/时间轴，按实际界面检查 `openai.chat`、`exec_tool` 等节点。读取真实工具名、业务参数、原始返回与后续恢复，外层包装成功不代表内层有数据。
5. 对“已保存、已发送、已展示”逐项找调用与独立证据；对耗时比较实际节点时间，不用模型自填日志时间。没有对应证据不归因模型、网络或图片工具。

大型响应显示截断时找“查看完整内容/完整结果”，取得完整文本再解析。UI截断不证明接口丢数；管理界面能读全，也不证明Agent把原始结果保真传给了工作流。

工具schema错误按具体参数路径修正，不解释成授权不足。历史观察有：record_id要求数组、search要求keyword和search_fields、sort要求object；这些不是通用常量，当前schema优先。周期列表优先实际列表方法，无排序需求可省略sort。请求失败不是零记录。

401 `this key is not enabled`、402 `Insufficient Balance`曾出现在模型网关层，不能据此判断Lark或网站权限失效。保留真实trace，停止无新证据的重跑。用户暂停后不因服务恢复自动继续。

## Skill 替换与发布

1. 核对资源ID、引用应用、生效版本、当前正文与未知草稿，保留备份。
2. 编辑 → 替换技能包 → ZIP/文件夹。历史ZIP结构为 `<skill-name>/SKILL.md`；只含本次目标及必要MD参考。核对新增/修改/删除，包外文件可能被移除。
3. 保存草稿，等待状态完成。在编辑态预览关键正文，再发布新版本；保存草稿与发布分开。
4. 发布后重新加载，核对版本和真实正文，包括新增与应移除规则。曾有新标签配旧正文的个例，原因未定，不能当普遍缺陷。
5. 已正确挂载的Skill曾在新正式会话自动加载最新发布版，无需无故移除重加。旧会话刷新时间未验证；实际加载内容仍须核对。

初次导入曾直接上线默认版本，检查现状后再决定是否另发版，避免为未变正文重复发布。

## Agent 配置、授权与版本

提示词、工具方法、模型、Skill是不同配置。添加能力分类及数量限制以当前UI为准；工具方法列表可能虚拟滚动，初始可见行不是全集。逐项勾选后等待真实状态，再核对完整方法清单。

挂载不等于账号授权。工具授权页单独选择当前任务合适连接；浏览器、本机CLI和云端Agent凭据分别判断，不导出凭据或暗换身份。

Tiptap页面存在多个contenteditable，区分提示词、欢迎语、调试与AI优化框。填入后读回完整语义；innerText空行变化可单独判断，但YAML缩进不能忽略。平台版本、配置版本与Skill版本分别记录。

修改前保留可恢复基线及完整草稿。发布会影响生效版本，只有本轮允许发布时才用发布保存基线；否则本地备份并保留已有发布版。回退区分“切换版本”与“覆盖到草稿”。

## 嵌套与工作流

Agent编辑 → 能力 → 添加能力 → 工作流/智能体。历史部署要求被引用资源先发布，且不能反向嵌套；避免 `A → W → A`。这不代表工作流不能使用独立智能体节点。

按下层到上层发布，读回实际绑定版本。曾观察上层明确固定 `version_number`，不能套用Skill最新版本行为。上层只读约束必须传给下层，不能因子Agent默认生产模式扩大任务。

工作流使用市场工具的一条已观察路径是：独立Agent先挂工具，再由智能体节点引用。插件列表为空不能证明不可调用。代码节点仅承担有实际需要的转换/校验，不假定第三方库可用。

原生智能体节点可选已发布资源，但Builder曾报 `workflow agent is unavailable`。核对真实参数与原生绑定，保留可用节点，不让助手反复删除重建。Builder校验失败与原生执行失败分开。

原生输出变量中选择JSON并配置JSON Schema曾改善可解析性；仅提示词要求JSON仍可能带围栏和开场白。structured_output仍是模型生成内容，不等于原工具响应。枚举转内部对象、required nullable被省略曾导致兼容失败；使用受支持的基础类型并在代码保留业务白名单与事实校验，不能用放松校验掩盖问题。

## Batch 与变量

- 历史原生Batch并行范围1–10，当前UI优先。input_var引用上游数组，output_var引用批内单项输出，外部result是聚合数组。
- 从批开始的连接点添加智能体曾自动放入批内；全局添加节点可能放到根层。检查节点归属、连接与实际输入。
- 使用原生变量菜单绑定Batch.item，不能因variables对象为空就断言未绑定；检查保存模板与本次渲染输入。对象模板渲染可能是字典表示，不能假定原样JSON。
- 上下游schema须相容，仅改引用元数据而不改上游类型可能让变量失效。空数组成功只证明空路径，不是有数据执行通过。
- “跳过并继续”可能留下null；按实际提交任务与稳定索引对齐，校验长度与来源。null是该任务失败，不编造正文或日期。

## AI 优化协作

先读真实配置、可用能力与版本，给一个目标、允许修改项、必须保留项和验收条件。目标已满足就不重复创建、挂载、发布或运行。备份包括提示词、模型、方法、变量、引用；Workflow还含节点、线、代码、异常策略与目的地。

完成后从原生配置读回差异。工具目录不等于已选方法，可绑定机器人不等于原授权身份，“Query data”说明也不证明聚合能力。发现范围外变化先恢复；助手“已完成”不代替配置。

先测受影响节点，再跑实际使用入口；上层固定版本须一起核对。失败无新依据就停止反复AI重建，按原生结果定位。

## 计划

计划详情 → 立即执行 → 最近执行 → 当前运行 → 查看运行。先核对应用、空间、初始消息、时区、排期及是否已有执行；手动验收不改生产排期，不重复创建计划。

编辑初始消息可能藏在“执行应用”的折叠区域。保存后读回应用、prefill与下次时间。日期滚轮曾出现选择与保存不符，改用原生Cron后仍需以详情下次时间验收，不能照抄历史Cron。

手动执行成功不证明定时触发；只有任务要求验证调度器时，才等真实排期或创建授权的一次性测试计划。新建后直接进入详情不代表创建失败。平台完成不代表业务字段/附件通过。

## 业务附件与链接提示

真实记录分享token不等于record_id，不拼 `/record/<record_id>`。从原生分享入口取得链接并实际打开。

替换附件先上传、追加、独立读回新版，再移除旧引用；失败保留已有成果。导出文件中的“尚未保存”等临时文案在保存后可能过时，局部修订检查真实diff。

历史Lark附件下载工具要求 `extra: {bitablePerm: {tableId, attachments: {[fieldId]: {[recordId]: [fileToken]}}}}`，错放tableId层级曾返回400。调用前核对当前schema与授权，不据两个文件同时失败就断言通道故障。

Lark视图筛选可能需点击保存才变为共享配置，切换字段类型可能重置操作符。保存后用真实filter及view_id查询；视图删除与记录删除分开。
