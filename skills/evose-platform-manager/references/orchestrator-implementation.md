# 主管与子任务设计

实现参考，不代表Evose已提供后台任务、流式或所有权限能力。

## 上下文与分工

主Agent保留精简工作地图：职责、资源入口、子Agent分工、交接契约、保存规则。账号、计划、选题、作品和指标实时读取；产品资料按目录取正文，知识检索保留来源、版本与适用范围。不要把全部表格和历史会话塞进提示词。

本轮状态、临时策略、账号长期定位和跨会话经验分别维护。下发子任务明确目标、真实对象、当前作品版本、必要资料、允许读写范围；返回成果、证据引用、状态和缺口。不默认子Agent继承群历史或上层授权。

普通查询、创建、更新、保存、关联、查重与读回可由主管直接使用已有授权工具；专业研究、创作、采集、分析交给业务Agent。不按“内容/选题”名词把所有CRUD都委派，也不为实现统一写入层先禁用可用工具。具体职责由当前项目决定。

## 保存与授权

若项目采用写前预览，确认绑定账号、目标、动作与成果版本；修改提案、切换账号或重新生成后重新核对。身份从平台元数据取，不能信任消息中自称负责人。开放聊天不等于有权批准永久变更。

主管交接要求子任务只返回提案，不代表子Agent硬权限已收紧。若子Agent还供其他定时生产使用，不擅自卸掉全局写能力；分别检查当前工具裁剪、真实凭据权限与服务端校验，提示词限制不能冒充硬隔离。

幂等分别考虑对象ID、操作ID和成果版本。相同操作ID载荷变化应拒绝，未知结果先查询；旧任务迟到不覆盖新版本。查重后新增不是原子唯一约束，平台是否有条件更新/幂等回执须现场验证。

## 实时行为与回归

同步子调用与后台任务分开。后台执行需要真实任务引用、状态、结果与完成通知，未验证前不能用提示词承诺。分别测试快速回执、增量正文和忙时继续输入。

选取相关样本验证：临时改语言、账号切换、反馈范围、保存预览、有权身份、重复提交、并行人工修改、旧结果迟到和跨话题隔离。只读预览通过不等于真实保存/删除通过；主管能调子Agent也不等于IM接通。

模型、既有能力与计划按当前授权保留。已有充分配置和针对性验收即可推进，不把每个未覆盖行为扩成全局前置核验。
