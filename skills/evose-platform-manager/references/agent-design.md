# 结构与提示词

以下为历史项目提炼的设计判断，应用前核对真实需求与平台能力。

## 优先理解和复用

改造前读取系统提示词、挂载工具/Skill、真实字段类型、输入来源、人工审核与调度入口。保留可用的创作、采集和通知能力；名称存在、已挂载、已授权、实际调用成功是四种不同状态。

先用现有原生工具与纯 Markdown Skill 跑最小链路。固定转换或可靠校验有实际缺口时，再加工作流代码组件；不要为研究原始结果透传而阻塞已能直接调用原生工具的路径。

历史部署中云端 Skill 只能保存 Markdown，工作流代码组件不能使用第三方库。ZIP只是导入载体，沙箱出现过脚本也不证明可长期分发执行。代码组件的语言、标准库、网络、文件和持久化能力逐项核验，不假定可 pip/npm 安装。

若用户另要求本地 Agent 外壳，优先复用官方 Pi 的运行循环、工具与会话接口，使用明确依赖版本及锁文件；这是新增开发的选择，不意味着 Evose 底层已经使用或迁移到 Pi。

## 职责分工

| 位置 | 维护内容 |
|---|---|
| 系统提示词 | 角色、意图路由、事实/权限边界、交付要求 |
| 集中配置区 | 工具名、目的地、字段映射、上限、重试、功能开关、模型选择 |
| 业务 Skill | 取材、查重、创作、保存、验收和恢复的方法 |
| 专业 Skill | 渠道表达、品牌视觉、写作或分析方法 |
| 工具/程序 | 真实读写、数据校验、可靠时间、可证明的原子操作 |
| 计划初始消息 | 选择任务与配置，不复制整套规则与另一份阈值 |

提示词按职责用 Markdown 分节；必要配置可集中为 YAML 文本，但不能据此假定 Evose 会自动插值或校验。API字段保持真实名称；业务维护键可中文化，改键时同步所有引用，不并存两份权威配置。

开关允许尝试某能力，不代替账号授权或明确目的地。上限注明计数粒度；重试注明是否包含首次。字段缺失、类型不符时给具体缺口，不由 Skill 偷补同名默认值。模型使用当前项目选择，参数/权限/余额问题不先归为模型不足。

## 动态数据和保存

账号定位、周计划、作品与指标从当前数据库读取，不硬编码到通用提示词。冻结快照保留一次分析依据，不替代实时业务数据。字段描述与名称不证明类型；以当前 schema 为准，公式与更新时间字段不能当普通可写文本。

当前作品要求、临时策略和长期定位分开。允许在对话中逐步补充，先交付试用成果；一句“不喜欢”不自动成为账号长期禁令。永久保存与确认规则由当前项目配置，若使用写前预览，绑定具体账号、记录、字段及成果版本；变化后旧确认不能继续套用。

草稿、人工采用、定稿、发布是不同动作。历史勾选不自动采用新返工版本。未知负责人不编造，IM开放使用也不等于有权批准永久变更。

## 意图路由与恢复

用户直接询问候选、查看成品、局部改稿，不套用自动扫描的领取条件和模式口令。先读取聊天与关联资料，再问仍影响结果的具体缺口；字段空不证明没有素材。返回完整正文与真实可见图片，状态与记录链接简短补充。

已有图文只缺归档时补缺项，不再次付费生成；同一作品局部修改保留其他要求。未知异步结果先查原任务。受阻保留阶段、任务引用和已有成果，不用单一空字段同时表示进度、排期和结论。

日常新增与用户点名修复原记录分别路由。已有记录时定位原对象，只修本轮指定事实；不能用“扫描不覆盖”拒绝已授权修复，也不能另建同帖规避。

普通查重后新增不提供并发唯一保证；提示词“先领取”也不能实现原子锁。可靠顺序、去重和条件更新有需求时，先核验平台原生能力，再做最小工具适配。

## 数据与交付契约

- 明确正文、简报、来源链接、当前版附件、状态分别是否必填；工具 success 不证明未提交字段已填。
- 图片生成、素材上传、记录追加、独立读回分开。旧图片不代替新版本归档；附件 token 不是可见图片。
- 时间保留来源精度和时区，显示到分钟不表示只能保存分钟。发布时间、观察时间、计划时间、执行时间分开；迟到观测不能伪装准点历史快照。
- 多渠道使用共享事实字段和渠道校验。网站没有发布日期保留未知；搜索摘要、模型整理与来源原文区分。X原创/引用形式与媒体类型分开，不能把候选筛选规则扩大为发布账本规则。
- 原始矩阵按本次字段元数据映射，不用固定列号或模型手工重排。结构化输出只保证格式，不证明来源保真。
- 报告区分观测、假设和编辑判断；无同窗口对照不直接比较裸指标，无实际目检不评价图片质量。

先最小字段筛选，再加载当前任务所需资料；同轮复用品牌上下文。裁剪工具方法后仍需实测，未测量就不声称降低 token 或提高成功率。
