# 对话案例与回归

以下是脱敏的设计示例与预期，不代表本包已在目标Agent完成测试。先用[观测追踪](../../evose-platform-manager/references/operations.md#观测追踪与故障定位)核对真实失败。

| 用户请求 | 常见失败 | 合理行为 |
|---|---|---|
| 这周有什么值得写？ | 拒绝选题，索要扫描口令 | 读取现有资料，给少量候选与理由，不启动制作 |
| 我想写产品更新 | 先要求选题库存在同名记录 | 围绕题目读内部权威资料，核对近期事实再给方向 |
| 先放下这个，看看今天的热点 | 继续追问上一任务选项 | 切换目标，保留新任务所需上下文 |
| 就写第二条，发英文图文 | 重复问渠道、语言和ID | 结合已展示候选定位并执行，缺口读完资料再问 |
| 给我看看刚才的正文和图 | 只报完成、给token或重新生成 | 展示已有全文与真实图，准确说明保存状态 |
| 太像公关稿，口语一点 | 重走首次生产问卷 | 修改当前版本语气，保留事实、对象和无关要求 |
| 只改文字，别改表 | 为归档流程写库 | 对话交付文字，保持表格不变 |
| 保存刚才那版 | 再次生成或保存另一版 | 复用同一成果，按本项目实际保存授权执行 |

## 只问真实缺口

已读关联资料、事实足够但渠道确实未知时，可问“这篇准备发在哪个平台？”；渠道已经给过就不能套用该问题。关键事实不能猜，可修改的呈现偏好可先按上下文给工作稿。

标题类似的两条都匹配时，问“英文短帖那篇，还是中文长文那篇？”，用实际差异帮助定位，不要求用户找记录ID或补整张表。

## 部分成功

正文和图片已有、附件归档失败时，实际展示已有成果，再说“图片还没存进表格，补存会沿用这张”。不能只有这句话而不展示图；也不能承诺尚未验证的自动恢复。

未知调用结果先查原任务，能在既有授权内修正参数就继续；确需用户介入只指出最小缺口。生成、保存、发送与显示分别描述。

## 回归判断

同条件比较首个有用结果的时间、无效追问、上下文连续性、可见成品、真实工具调用与业务状态。不只比较字数或语气。最终图片要实际加载，读取图片工具成功不代替用户看到了图。

功能关闭要验证实际调用是否关闭，不能只看系统写了“不读”。改提示词后检查新会话是否使用新规则。英文中间过程是否计缺陷取决于当前用户体验要求，不据此单独判模型能力。

成本和质量同看，人工停止样本不计完整成功，不同后续任务的累计耗时不能当严格模型对照。保留实际失败、人工纠正和未测范围。
