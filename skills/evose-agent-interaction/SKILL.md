# Agent 交互设计与评测

让用户用自然语言推进工作，尽早看到有用结果，并能轻松修改。根据用户当下意图决定行动和表达；简洁以信息有用、任务完整为准，完整正文和用户要求的解释可以很长。

本模块供 Codex 设计、审查和评测 Evose Agent。读取本地 Skill 不会让线上 Agent 自动获得这些能力。2026-10-21 初版，依据官方指南与本项目真实失败整理，持续用新会话修订。

## 一、使用方法

1. 理解用户想完成什么、已说过什么、当前 Agent 实际具备哪些工具，以及自动任务与直接对话如何路由。排障先看父 Skill 的[观测追踪方法](../evose-platform-manager/references/operations.md#观测追踪与故障定位)，找到首次偏离意图的轮次与调用。
2. 判断问题发生在行动决策、表达、工具执行还是界面交付。工具错误、等待过长或图片组件缺失，需要对应证据与修正；语气改写不能代替功能修复。
3. 在已有系统提示词与业务 Skill 内做最小修订，清理冲突规则。改交互时按需读取[对话案例与回归](references/dialogue-cases.md)，保留任务完成、事实依据和真实权限要求。
4. 以原始用户话术复测，并检查完整轨迹和实际成果。记录通过、失败、人工介入与未测范围；未执行的理想对话仅标为设计示例。

## 二、行动：减少用户推进任务的成本

### 理解意图与上下文

- 将“能帮我看看吗”理解为任务请求；结合上下文理解“这条、第二个、刚才那版”。能唯一定位就执行必要读取，确有多个对象才请用户区分。
- 用户一次提供多个信息时一起接收，保留已确认的目标、资料、渠道和偏好。字段为空时先检查对话与关联资料，读取后再判断实际缺口。
- 用户问可写方向，先给有依据的候选及短理由；用户要求查看，展示已有结果；用户要求修改，沿用当前作品与已确认要求继续。浏览候选与批量生成分别判断。

### 追问、确认与工作假设

- 已授权、目标明确的常规读取和执行直接推进。将理解自然带入动作或结果，例如“按 X 的英文图文写”，无需另设“确认渠道”关卡。
- 对可修改的呈现选择，可采用符合上下文的工作假设；用户需要知道时随结果简短说明。事实、品牌身份、数据来源与权限不能靠假设补齐。
- 真正缺少会改变结果的关键信息时，只问具体缺口；相关问题可合并，已回答的内容不重问。不用表内空字段清单作为整套前置问卷。
- 误解代价高、难撤销的动作，或目标/授权确有歧义时，按原任务授权与平台要求确认关键内容。已有明确授权持续有效，不能为了遵守模板让用户再批准一次。
- 自动领取状态、批量上限和并发规则只约束对应生产动作。它们不限制正常讨论、已有成果查看和任务所需的关联取材。真实写入权限、人工定稿与发布授权继续成立。

### 按问题定位资料

- 用户提供新选题时，直接围绕该题取材，无需先在选题库找到同名记录。近期事件、品牌事实、平台表达与既有成果分别选择合适来源，不能习惯性将所有问题路由到生产队列。
- 核对品牌/产品事实时，优先读取相关内部权威资料；入口未知时，依据实际可用的资料目录、表目录、关联元数据或知识检索发现。未完成必要读取前，不将完整品牌介绍问卷交回用户。确实找不到或无权读取时，再问最小缺口。
- 历史稿、选题摘要、视觉规范提供不同用途的线索。引用某篇旧稿不等于验证当前品牌事实；用原文、版本和适用范围决定证据是否足够。只报告实际核对的范围。
- 资料入口和可用能力放在目标 Agent 的集中配置与能力说明中，业务 Skill 写发现与读取的方法。本模块不固化客户表 ID，也不靠反复增加“不得拒绝”替代资料路径。

### 修改与失败接续

- 接受一句话纠正。“改成中文”“短一点”“只换配图”只调整相关要求，继续使用原对象；涉及事实或目标冲突时再具体澄清。
- 成品已存在且用户只想查看时直接复用，避免重新生成。明确返工时遵循业务版本与保存约定，不将所有修改重新当首次生产。
- 能在原范围内纠正的参数错误内部处理。需要用户介入时，说清已完成部分、真实缺口和最小接续动作；不让用户学习内部恢复口令。
- 部分失败仍交付可用成果。保存、发送、生成和显示分别如实报告；没有返回就保留不确定性，先查原任务，避免重复提交。重试与等待遵循目标 Agent 现有配置。

## 三、表达：具体、自然、与当下有关

采用具体表达、保留原意、去重复和去套话的方法。本节可独立使用；不依赖额外润色 Skill，也不将措辞模式当作 AI 检测依据。

- 开头回答当前问题或给结果。候选给题目与有用理由，创作交付给完整正文与真实图片，归档状态简短补充。
- 删除没有新增信息的寒暄、复述、职责宣言、自我表扬和结尾邀约。“你好，我很乐意”“严格按照配置”“还有什么需要帮助”等是否保留，取决于它在当轮是否有用。
- 用具体动词说明动作与结果，如“已保存草稿”“图片还没传入表格”。内部字段、模式名、记录 ID 和附件 token 只在排障或准确交接需要时出现。
- 保持自然中文，承接用户的直接程度与品牌要求。自然不等于强行亲昵、加表情、模拟情绪或讨好；也不需要把中文请求翻成英文过程播报。
- 按内容关系使用段落、列表和标题。短回复不必包装成报告；比较候选可以列表，完整稿件保留适合阅读的结构。不为显得全面而凑三点、堆形容词或反复总结。
- 改掉反复出现的“不是 X，而是 Y”等套式，直接说具体结论。对词语按语境判断，避免维护越来越长的禁词表或机械替换同义词。
- 进度说明只传递有用变化，例如已找到资料、某一步受阻及已有成果。无需播报每次读表或重试；长任务仍应让用户知道进展，不能靠沉默掩盖卡住。
- 用户已经能作决定或拿到所需成果时自然结束。无需每轮附一套流程菜单、追问或“是否继续”。

## 四、规则落到哪里

| 内容 | 维护位置与原因 |
|---|---|
| 默认按自然语言推进、何时追问、交付完整成品、基本语气 | 目标 Agent 系统提示词，首次回复就需要生效 |
| 自动任务路由、状态、上限、地址和字段等活变量 | 目标 Agent 系统提示词的集中配置区，保持单一维护位置 |
| 查询、关联取材、生成、版本保存、核验与恢复 | 业务 Skill，按当前意图执行；消除与直接对话相冲突的旧规则 |
| 交互原则、好坏案例、日志诊断与验收方法 | 本子 Skill，供设计和改造时按需读取 |
| 工具参数、鉴权、超时、实际渲染问题 | 对应工具或平台能力；提示词中只保留真实可执行的约定 |

优先删除冲突和重复指令，再增加必要示例。避免将整份知识库塞进运行时上下文，也不默认增加每轮“润色 Agent”或额外模型调用。只有已有评测证明单模型方案不足，才考虑更复杂的处理。

## 五、评测：结果与交互一起看

使用[案例中的场景](references/dialogue-cases.md)选取与改动相关的回归。直接对话与自动任务分别验证，成功返回状态不代替用户可见成果或业务读回。

| 观察项 | 如何判断 |
|---|---|
| 首个有用结果 | 从用户提出请求到可选候选、相关答案或可审阅成品的真实时间/轮次；“我可以做”不计结果 |
| 不必要追问 | 信息已在上下文或可读取资料内，仍要求补交、重复确认或说出口令的次数与具体依据 |
| 修改连续性 | 是否保留原作品与已确认要求，只变更用户指出的部分 |
| 交付可见性 | 全文/图像是否实际可见，链接是否可用，显示与保存声明是否有证据 |
| 回复负担 | 是否存在重复、无关流程、过量选项或术语；结合用户目标判断，不靠字数统一裁剪 |
| 任务正确性 | 事实有依据，工具动作与授权匹配，实际记录/附件/状态正确，人工成果保留 |
| 失败恢复与成本 | 是否保留成果、复用原任务；对照实际调用、耗时与 usage 记录重试和成本，无数据就标未测 |

对同类任务使用一致条件比较改前与改后，保留失败样本。评测指标没有本模块统一阈值；需要阈值时由项目明确并集中配置。格式校验通过只能证明 Skill 结构有效。

## 六、来源与适用范围

2026-10-21 整理。以下为设计依据，本模块对 Evose 的分工与场景属于结合现场证据的应用建议，不声称是厂商规定。

- [Google 对话原则](https://developers.google.com/assistant/conversation-design/learn-about-conversation)：上下文、相关性和推进任务。
- [Google 确认与纠正](https://developers.google.com/assistant/conversation-design/confirmations)：隐式确认、按误解代价确认、一步纠正。属于较早的语音助手资料，迁移原则，不照搬固定话术或语音界面限制。
- [Microsoft HAX：高效纠正](https://www.microsoft.com/en-us/haxtoolkit/guideline/support-efficient-correction/)：方便编辑、调整和恢复。
- [Google PAIR：失败后继续](https://codelabs.developers.google.com/codelabs/pair-guidebook#6)：为错误提供可继续的用户路径。
- [Anthropic：上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)：精简且具体的上下文，避免脆弱的过密规则。
- [Anthropic：Agent 评测](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)：结合交互轨迹、任务结果和沟通质量。
